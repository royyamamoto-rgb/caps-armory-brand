## Why blocked

`@capsarmory/scope-reservation@0.0.0` exists under the `lumina28` npm account
(parent's Task 1), proving the scope is owned. Publishing a new package under a
scope still requires explicit authorization:

- Either an `NPM_TOKEN` secret with publish rights on `@capsarmory/brand`, **or**
- npm trusted publisher (OIDC) configured for this repo + the `release` workflow.

The release workflow ships with `permissions: id-token: write` and is wired for
OIDC; once the trusted publisher mapping is added at
`https://www.npmjs.com/package/@capsarmory/brand/access` (Repository:
`royyamamoto-rgb/caps-armory-brand`, Workflow: `release.yml`, Environment:
`release`), a re-run will publish without any secret-token round-trip.

## Resume after auth lands

Trigger the workflow again — the local version (`0.0.1-alpha.0`), changeset,
and pre-release state are all baked into `main`. No code changes are required:

```bash
gh workflow run release.yml --repo royyamamoto-rgb/caps-armory-brand --field dist_tag=alpha
```

Then approve the `release` environment deployment and watch:

```bash
gh run watch --repo royyamamoto-rgb/caps-armory-brand --workflow=release.yml
npm view @capsarmory/brand@0.0.1-alpha.0 dist-tags
```

Expected: `alpha: 0.0.1-alpha.0` and the package detail page on npmjs.com
shows the sigstore provenance badge once `--provenance` is re-added (currently
omitted to surface the auth failure cleanly).
